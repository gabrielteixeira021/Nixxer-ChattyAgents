# ADR 006: Dedicated Local Persona API

- **Status:** Accepted
- **Date:** 2026-10-06
- **Decision owner:** Gabriel Teixeira
- **Record author:** Codex
- **Milestone:** PE2

## Context

SophIA needs to read a persona snapshot from its desktop runtime without
linking C++/Godot to Python, SQLAlchemy, or the Persona Engine database. The
existing web application also starts inference and presentation concerns that
are unnecessary for this integration.

### Requirements

- **RF-PE-002 — Local snapshot API.** A versioned endpoint must return the PE1
  snapshot and explicit contract errors.
- **RNF-PE-002 — Local-only boundary.** The MVP must bind to loopback by
  default and must not require an external network, LLM, or production data in
  its tests.

## Decision

PE2 adds a dedicated FastAPI composition root at `src.backend.persona_main`.
It defaults to `127.0.0.1:8765`, initializes persistence only, and publishes:

- `GET /v1/health`
- `GET /v1/personas/{character_id}/snapshot`

The canonical machine-readable contract is
`docs/en/api/persona-v1.openapi.yaml`. Error bodies use one stable envelope and
omit internal exception details. The domain service remains framework-free;
the API adapter owns database lookup and response mapping.

## Impact analysis

- **Direct:** SophIA gains a process boundary it can consume in PE3.
- **Indirect:** the legacy FastAPI/React application and its LLM lifecycle are
  unchanged.
- **Data:** no schema, migration, or write path is added.
- **Operations:** Persona Engine is a second local process on port 8765.
- **Rollback:** revert the PE2 API feature and documentation commits; no data
  rollback is required.

## Alternatives rejected

- Mount routes in the legacy application: rejected because it would couple
  SophIA startup to frontend and inference concerns.
- Link Python directly into Godot: rejected because it increases packaging and
  ABI complexity before the contract is proven.
- Bind to all interfaces: rejected because the MVP has no authentication and
  requires no LAN access.

## Risks

| Risk | Probability | Impact | Mitigation | Owner | Status |
|---|---|---|---|---|---|
| Port 8765 is already occupied | Low | Medium | Make the runner port overridable; keep 8765 as the documented default | SophIA maintainer | Monitored |
| Static and runtime OpenAPI drift | Medium | High | Compare response codes, references, parameters, and schemas in automated tests | Persona Engine maintainer | Mitigated |
| Local database is unavailable | Low | High | Health returns a stable 503 without leaking internal details | Persona Engine maintainer | Mitigated |
| Synchronous SQLite reads briefly occupy the API event loop | Low | Medium | Keep PE2 read-only and single-client; measure before introducing async persistence | Persona Engine maintainer | Accepted for MVP |

## Consequences

PE3 can implement a small HTTP adapter without knowing the persistence model.
Response generation, memory retrieval, state mutation, TTS, and LAN exposure
remain outside this milestone.
