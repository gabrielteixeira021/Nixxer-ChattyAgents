# ADR 007: One Continuous SophIA with Selective Memory

- **Status:** Accepted; implementation pending
- **Date:** 2026-10-07
- **Decision owner:** Gabriel Teixeira
- **Record author:** Codex
- **Milestone:** PE4
- **Commitment:** owner commits; maintainers agree

## Context

The inherited Open-ChatBot application organizes characters, chats, storylines,
scenes, full message history, journals and vector memories. The SophIA desktop
MVP is a different product: one continuously present character and assistant.
The user does not create a new chat, switch scenes or reset SophIA's identity.

PE4 must preserve useful facts across restarts without retaining every spoken
interaction. Audio, full transcripts and model replies can contain personal or
sensitive data and are not durable memory by default.

## Decision

The MVP resolves exactly one logical SophIA identity. The numeric character id
in Persona API v1 remains a compatibility detail until a later API version; it
is not a product-level character selector.

Memory is separated into three responsibilities:

- recent working context, bounded and disposable;
- durable normalized memories for selected facts, preferences and commitments;
- a content-free operational audit of memory management actions.

Durable memories have a category, normalized content, provenance, revision and
timestamps. Users can inspect, correct and forget them. Correction deletes the
superseded content; forgetting removes every revision, relational/vector
representation, metadata, cache and audit payload. Only a content-free
tombstone may remain. Retrieval is global to SophIA, limited to 8 records and
1,024 estimated tokens, deduplicated, sanitized and independent of legacy
`chat_id` or scene state. Each record is capped at 2,048 UTF-8 bytes.

Only `preference`, `personal_fact` and `commitment` enter PE4. Explicit remember
requests persist directly; inferred candidates need confirmation and expire in
7 days. Completed commitments expire after 30 days. Facts and preferences stay
until corrected or forgotten. Credentials/tokens and raw interaction artifacts
are ineligible; sensitive data needs purpose-specific confirmation. The store
holds at most 1,000 active memories and fails clearly at capacity.

Provenance stores source type and timestamp, not raw audio, a complete
transcript or a complete model reply. Expiry uses the same complete-removal path
as forgetting across relational/vector representations, metadata, caches and
audit payloads; at most a content-free tombstone remains.

The PE4 migration is additive and reversible. It does not backfill legacy chat
messages, journals or vector documents into the new store automatically. Legacy
tables remain intact but outside the SophIA MVP contract.

## Impact analysis

- **Direct:** Persona domain, persistence adapter, local API contract and tests.
- **Indirect:** snapshot prompt construction and the desktop Persona consumer.
- **Data:** a new memory representation and migration; no destructive rewrite.
- **Privacy:** smaller retained dataset plus granular access, correction and
  deletion.
- **Rollback:** disable the PE4 read/write path and leave its schema/data inert.
  A down migration is forbidden until export, backup, restore and re-upgrade are
  proven without loss.

## Alternatives rejected

- One memory scope per chat/session: rejected because those are not SophIA
  product concepts and would fragment one identity.
- Persist every transcript and reply: rejected by data minimization and the
  owner's requirement for selective memory.
- Reuse legacy chat vectors through automatic backfill: rejected because it can
  import stale, hostile or irrelevant roleplay history without consent.
- Remove legacy tables immediately: rejected because it makes rollback and
  comparison unsafe.

## Risks

| Risk | Probability | Impact | Mitigation | Owner | Status |
|---|---|---|---|---|---|
| Model stores an incorrect personal fact | Medium | High | Inspect/correct/forget APIs, provenance and revision | Persona maintainer | Open for PE4 |
| Hostile memory injects roles or policy | Medium | High | Normalize, sanitize, type and cap retrieved memory | Security owner | Open for PE4 |
| Migration damages existing data | Low | High | Additive migration, backup, forward/rollback tests, no backfill | Persistence maintainer | Open for PE4 |
| Memory grows without bound | Medium | Medium | Deduplication, category policy and bounded retrieval/retention | Persona maintainer | Open for PE4 |
| Sensitive data is retained accidentally | Medium | High | No raw audio/transcript/reply retention; explicit data inventory and deletion tests | Privacy owner | Open for PE4 |

## Consequences

PE4 stops at identity, selective memory, management operations, content-free
memory audit and non-destructive rollback. Task execution/state, tools,
connectors, multiple characters, narrative scenes and a complete settings UI
remain outside this milestone.
