# ADR 005: SophIA Persona Engine Boundary

- **Status:** Accepted
- **Date:** 2026-10-06
- **Decision owner:** Gabriel Teixeira
- **Record author:** Codex
- **Milestone:** PE1

## Context

SophIA needs a persistent character runtime without coupling its Godot desktop
shell to this repository's FastAPI, SQLAlchemy, React, or llama-server details.
The original Open-ChatBot domain already owns character identity, behavioral
state, memory, lore, reflection, and prompt composition.

### Requirements

- **RN-PE-001 — Persona snapshot.** The engine must produce a versioned system
  prompt plus character name, mood, dynamic/static mode, and source revision.
  Acceptance: deterministic unit tests cover populated, invalid, and hostile
  inputs. Origin: Gabriel, architect and product owner. Status: approved.
- **RT-PE-001 — Framework independence.** The snapshot service must not import
  FastAPI, SQLAlchemy, or database models. Acceptance: the service accepts
  structural objects and its focused tests use only test doubles. Origin:
  SophIA ADR-003 and REGARCH-SW-002. Status: approved.

The first milestone does not expose HTTP, call an inference engine, mutate
state, retrieve memories, or synthesize audio.

## Decision

The repository and product module are named **SophIA Persona Engine**. The
domain service `PersonaEngine.build_snapshot()` is the first public contract.
It returns the immutable, schema-versioned `PersonaSnapshot` value object.

Prompt-text sanitization and bounding are shared with the existing `Brain` so
the standalone contract and chat flow cannot silently diverge. Token limits
are constructor inputs, keeping the domain independent from Pydantic settings.

SophIA remains responsible for microphone capture, speech recognition, desktop
state, playback, and animation. Persona Engine owns character identity,
relationship, memory, prompt composition, and stylistic realization of a
factual result. ADR-008 supersedes the broader "response policy" wording:
Persona never owns credentials, tool policy, permission, validated arguments
or factual results. Voice synthesis may later sit behind a port.

## Impact analysis

- **Direct:** `Brain` delegates three text helpers to `core.persona.text` with
  the same signatures and behavior.
- **Indirect:** prompt-building tests protect memory, summary, card, and anchor
  sanitization from regression.
- **Data:** PE1 adds no schema, migration, write path, or persisted user data.
- **Rollback:** revert the PE1 feature commit; no data rollback is required.

## Alternatives rejected

- Embed SQLAlchemy models in the public contract: rejected because it couples
  SophIA to the private persistence schema.
- Replace this runtime with OpenJarvis: rejected because its generic agent stack
  does not replace Open-ChatBot's character simulation.
- Move all prompt assembly at once: rejected because it creates a large,
  difficult-to-revert behavioral change before the contract is proven.

## Risks

| Risk | Probability | Impact | Mitigation | Owner | Status |
|---|---|---|---|---|---|
| Persona snapshot diverges from full chat prompt | Medium | High | Share text guards now; migrate composition in later tested slices | Persona Engine maintainer | Monitored |
| System prompt grows beyond the local model window | Medium | Medium | Preserve configurable bounds; add exact budgeting in PE2 | Persona Engine maintainer | Open |
| Dynamic state semantics remain ambiguous across chats | High | High | ADR-007 defines one continuous SophIA identity independent of chats/scenes | Gabriel | Resolved by ADR-007 |

## Consequences

SophIA can consume a stable personality snapshot without accessing this
repository's database. The contract is intentionally incomplete until PE2 adds
a versioned local service boundary.
